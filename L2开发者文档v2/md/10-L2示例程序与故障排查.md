# L2 示例程序与故障排查

[返回文档总览](../总体介绍.md) | [SDK 快速开始](./06-L2SDK快速开始.md) | [SDK 接口参考](./07-L2SDK接口参考.md) | [控制权、任务与外设控制](./09-L2控制权任务与外设控制.md)

## 示例程序

SDK 的 `example/` 目录包含以下程序：

| 文件 | 用途 |
| --- | --- |
| `data.cpp` | 连接、设备信息、状态、传感器和故障回调 |
| `control.cpp` | 综合姿态、运动、灯光和数据配置 |
| `async.cpp` | 异步连接、发送和回调 |
| `sync.cpp` | 同步连接和同步命令 |
| `manual_reconnect.cpp` | 主动断开与手动重连 |
| `auto_reconnect.cpp` | 自动重连和连接状态处理 |
| `take_control.cpp` | 控制权申请、丢失和释放 |
| `camera_bitrate.cpp` | 相机码率设置 |
| `recharge.cpp` | 回充和离桩任务 |
| `led.cpp` | LED 自动模式、手动模式和灯效 |

## 编译

```bash
cd genisom_robot_sdk-main/example
mkdir -p build
cd build
cmake ..
cmake --build . -j6
```

运行格式通常为：

```bash
./<程序名> <机器人IP> 8082
```

## 推荐测试顺序

1. `data`：只读连接、版本、状态和故障。
2. `sync`：同步命令和超时处理。
3. `async`：异步回调和对象生命周期。
4. `take_control`：申请、丢失和释放控制权。
5. `control`：低速逐项测试支持的姿态和运动接口。
6. `camera_bitrate`：验证相机配置应答。
7. `led`：验证自动和手动灯效。
8. `recharge`：充电桩、地图和现场条件全部就绪后测试。

## data.cpp

第一次联调先运行：

```bash
./data <机器人IP> 8082
```

检查：

- `Connect()` 是否成功。
- 连接状态是否进入 `CONNECTED`。
- `GetDeviceInfo()` 是否返回正确设备类型和序列号。
- `Version()` 和 `SystemVersion()` 是否返回有效版本信息。
- `OnRobotStateData()` 是否持续触发。
- `OnFaultData()` 是否报告故障。

## control.cpp

综合控制示例包含多种通用接口。L2 系列运行时只测试能力表中支持的接口。以下接口会返回 `Errc::UnsupportedDeviceOperation`：

- `Slim()`、`DSB()`、`SkWalk()`、`Sand()`、`ReverseHeadTail()`。
- `BackLight()`、`ObstacleAvoidance()`。
- 点足设备上的 `Gait()`。

第一次运行时先禁用连续运动和跳跃相关操作，只测试软件急停、站立、卧倒、前补光灯和低速移动。

## async.cpp

异步模式适合持续运行的应用：

```cpp
client.StandUp(0, [](const std::error_code& ec, std::size_t) {
    if (ec) {
        std::cerr << "send failed: " << ec.message() << '\n';
    }
});
```

应用需要管理回调对象生命周期、线程退出、共享状态同步和断连后的停止逻辑。

## sync.cpp

同步模式适合启动阶段和单步测试：

```cpp
auto ec = client.StandUp(2000);
if (ec) {
    std::cerr << ec.message() << '\n';
}
```

不要在 SDK 回调中调用同步接口，否则可能阻塞内部通信线程。

## 重连示例

### manual_reconnect.cpp

手动重连流程：主动断开、等待状态变为 `DISCONNECTED`、重新连接、重新读取设备信息、检查急停和故障、重新申请控制权。

### auto_reconnect.cpp

```cpp
ConnectionConfig config;
config.connect_timeout_ms = 5000;
config.auto_reconnect = true;
config.reconnect_interval_ms = 1000;
```

自动重连只恢复连接。连接恢复后仍需重新确认控制权、任务状态、急停、故障和最后一次速度目标，不能自动恢复断线前的运动。

## take_control.cpp

关键回调：

- `OnControlLost()`：立即停止普通命令。
- `OnControlAvailable()`：通知工作线程可以申请控制权。
- `OnTakeControlAck()`：`error_code == 0` 才表示成功。
- `OnReleaseControlAck()`：确认释放结果。

## camera_bitrate.cpp

`CameraBitrateCmd` 使用 `camera_front` 或 `camera_back`，码率范围为 50000 至 100000000 bit/s。设备实际生效值通过 `OnUpdateCameraBitrateAck()` 返回。

## recharge.cpp

运行前确认充电桩、蓝牙配对、地图充电点和对接方向已经配置。任务判断区分三层：

1. 返回值或发送回调。
2. `OnStartRechargeTask()` 等命令应答。
3. `OnTaskStateData()`、机器状态和充电桩连接状态。

回充和离桩期间不要同时发送普通运动命令。

## led.cpp

LED 示例通常先调用 `SetLedAutoMode(false)`，再发送 `SetLedCommand()`。测试完成后调用 `SetLedAutoMode(true)` 恢复自动状态灯，确保告警和急停灯效正常显示。

## Connect 返回失败

依次检查：

1. 机器人是否完成开机。
2. 开发主机和机器人是否在同一网络。
3. `ping <机器人IP>` 是否正常。
4. UDP 端口是否为 `8082`。
5. SDK 与机器人系统是否能够完成握手，版本信息是否正常返回。
6. `ErrorHandler` 和返回的 `std::error_code` 内容。
7. 防火墙是否阻止 UDP 通信。

## ping 正常但握手失败

`ping` 只证明 IP 可达。继续检查：

- 机器人 IP 是否确为控制服务地址。
- `GetConnectionState()` 停在 `CONNECTING` 还是 `HANDSHAKING`。
- `ProtocolVersion()` 与机器人协议是否匹配。
- 是否错误地把 UDP 客户端连接到 WebSocket 端口。
- 机器人是否处于升级、关机或自检状态。

## 连接成功但控制无效

- 检查 `RobotState::control_source`。
- 调用 `TakeControl()` 并等待 `OnTakeControlAck()`。
- 确认 `ack.error_code == 0`。
- 检查软件急停和硬急停。
- 检查 `machine_status` 是否处于导航、回充、升级或安全状态。
- 检查调用是否属于当前设备类型支持的接口。

## 接口返回 UnsupportedDeviceOperation

这是 SDK 的设备能力保护。程序应停止重试该接口，并根据 `GetDeviceInfo().device_type` 隐藏对应功能。不要通过修改枚举值、强制类型转换或绕过 SDK 发送命令。

## 没有传感器数据

- 在 `Connect()` 前注册 `IDataCallback`。
- 保持回调 `shared_ptr` 存活。
- 调用对应的 `Set...Config()` 开启上报。
- 检查配置应答回调。
- 避免在回调中阻塞或抛出异常。
- 检查连接是否仍为 `CONNECTED`。

`RobotState` 和故障主动上报，高频 IMU、运动、速度和关节状态需要配置后才上报。

## 找不到 librobot_sdk.so

```bash
uname -m
find ../lib -name 'librobot_sdk.so*'
ldd ./data
```

设置对应架构的搜索路径：

```bash
export LD_LIBRARY_PATH=/path/to/genisom_robot_sdk-main/lib/x86_64:$LD_LIBRARY_PATH
```

ARM64 使用 `lib/aarch64`。出现 `Exec format error` 或无法加载时，通常是程序或动态库架构不匹配。

## 动作发送成功但状态没有变化

发送成功只表示命令通过 SDK 检查并进入通信流程。继续检查：

- 是否收到对应 `IControlCallback` 应答。
- `motion_status` 是否进入目标状态。
- 是否拥有控制权。
- 是否有急停、故障或任务状态阻止动作。
- 参数是否在有效范围内。

## 回充任务不执行

- 检查充电桩供电和蓝牙配对。
- 检查地图充电点及朝向。
- 检查 `charging_pile_connected`、`machine_status` 和 `TaskStateInfo`。
- 清理对接区域，确保雷达和相机无遮挡。
- 记录 `phase` 和 `error_code`。

## 程序退出处理

收到 `SIGINT` 或 `SIGTERM` 后按以下顺序退出：

1. 停止运动循环并发送 `Move(0, 0, 0)`。
2. 停止仍在运行的回充或离桩任务。
3. 恢复 LED 自动模式。
4. 调用 `ReleaseControl()`。
5. 调用 `Disconnect(true)`。
6. 停止应用工作线程。
7. 销毁回调对象和 `SDKClient`。
